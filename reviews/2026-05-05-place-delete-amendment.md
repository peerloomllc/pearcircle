# REVIEW — `place:{id}` soft-delete amendment

**Date**: 2026-05-05
**Tier**: T3
**Proposal**: `proposals/2026-05-03-wire-protocol.md` (amended)
**Decision**: `DECISIONS.md` 2026-05-05 — `place:{id}` gets soft-delete via optional `deleted`/`deletedAt` fields

Wire-protocol v1 §3 amended to add optional `deleted: boolean` and `deletedAt: number` fields to the `place:{id}` value, and §4 amended to clarify that a delete is a fresh write with `deleted: true` and a bumped `createdAt`. The same LWW-on-`createdAt` apply rule keeps the tombstone winning over older replicas without a new key kind, a new apply branch, or a `del` op type. Renderers (`circle:get` snapshot), `place:list`, and the in-process geofence tracker (`_circlePlaces`) all filter rows where `deleted: true`; the apply branch's `place:*` arm calls `untrackPlace` instead of `trackPlace` when a tombstone lands so the next `location:update` cannot fire transitions against a deleted place. Undelete is a non-deleted write with a newer `createdAt`. Old records without the fields are `deleted: false` (additive amendment). v1 remains the floor — no peers shipped beyond the two test devices, so this is an in-flight amendment, not a v1→v2 transition. Affects `src/bare.js` (`place:delete` IPC, `isDeleted`, `untrackPlace`, four filtered call-sites) and `src/ui/App.jsx` (Delete button per writable place row, two-tap confirm with 4s auto-disarm, edit-form auto-close on delete of the place currently being edited). Cross-device smoke on 2026-05-05: D1 deleted a place, D2 saw the row vanish from the bottom sheet and the cyan geofence circle disappear from the map within ~3s. Records remain in the underlying Autobase log; a 30-day retention sweep on `deleted: true && deletedAt < now - 30d` is a future slice if storage becomes a concern. Signed off by Tim.
